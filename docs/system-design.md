## 0. 現況摘要（v1.0.1，2026-10-06）

這一節是**唯一的現況描述**；後面各節保留設計過程與當時的決策，跟這裡衝突時以這裡為準。

- **產品**：退休實驗室-退休年齡試算。只算勞保、勞退、國保、健保（公教軍人、農民不適用），不算投資（存款利率當報酬）。兩種模式：**我自己**（反推最早幾歲可以退休）、**我和另一半**（三種安排：你先退、一起退、另一半先退，各自最早的時間，再用滑桿往後調；底下「每個階段」列出每一段每個月進出與存款變化）。結果一律標明是「剛好夠的最低門檻，不是建議的退休時間」。
- **資料**：會隨年度調整、有生效日的數字放 `data/*.csv`；法條規則、模型假設、產品規則放 `data/params.json` 並標 category（3.0 資料治理規則）。
- **程式**：`src/engine.js`（計算，瀏覽器與 Node 共用）、`src/app/` 15 個畫面檔（建置時依檔名接成一個函式，**不是獨立模組**，共用變數）、`src/pdfdoc.js`（PDF 排版）、`scripts/build.js` 產生單一 HTML。
- **隱私**：資料只存在使用者瀏覽器的 localStorage（**沒有加密**）；GA4 只在正式網域載入，事件白名單、不含使用者填的數字；匯出備份可加密（AES-GCM）。
- **測試**：引擎與制度規則、600 組標準答案、保險接續、夫妻規則與 solver、資料治理與語意一致性、畫面操作（單人、夫妻）、匯出入攻擊、無障礙（axe，jsdom）、PDF 產生與讀回；顏色對比用 `scripts/contrast-check.py` 在真的 Chromium 手動檢查（GitHub Actions 沒有跑）。
- **部署**：GitHub Pages，推到 main 就部署；Node 22.22.2 以上。
- **還沒做**：夫妻版 PDF、夫妻版的進階選項（工作空窗、勞退舊制、一次請領、勞保請領年齡）、夫妻方案參數比較、「保留緩衝」（使用者設定最後至少留多少）、存檔格式的 schema 與版本遷移測試、改成真正的 ES modules。

## 1. 產品定位

### 1.1 要回答的問題

> 靠本人這一份收入、**不靠投資**，最早幾歲幾個月可以退休，而且退休後仍能繼續負擔目前負擔的那一份家用？

平台採**個人分擔制**：只算使用者本人負擔的收支，假設配偶持續負擔其目前的家用份額。

### 1.2 設計原則

| 原則 | 具體做法 |
| --- | --- |
| 只問「會改變答案」的事 | 快速開始只問現在就知道的數字，約 2 分鐘出第一版結果 |
| 不讓使用者把結果調漂亮 | 報酬率不開放調整；通膨只提供 2%、2.5%、3%，沒有更低的選項 |
| 不靠投資 | 名下的錢一律假設放銀行定存；投資的效果是另一個專案（SP2）的範圍 |
| 制度數字有官方來源 | 所有制度參數放在 `data/`，每一列都寫來源；關鍵公式用官方試算器實測驗證 |
| 資料不離開使用者的裝置 | 沒有伺服器、沒有帳號，方案只存在瀏覽器的 localStorage |
| 介面越簡單越好 | 只留一個色塊；可調整的東西集中在「調調看」；細節預設收起 |
| **任何變動都同時講時間和錢** | 最快退休怎麼變＋在固定時間點退休的錢怎麼變（第一位測試者的回饋）；時間卡住時（例如 65 歲還不夠），錢仍看得出變化 |
| 原始不動、調整後對照 | 有調整（調調看或還沒套用的實際資料）時，結果改成「原始 vs 調整後」兩欄；上半部條件、下半部結果；原始那欄永遠不動 |

### 1.3 確定不做

配偶資料與雙人模式、信用卡循環、機動利率模擬、動態提領策略、報酬率波動與序列風險、遺產規劃、保險需求分析、**勞保月領與一次領的建議**（不做的是「建議」；兩者的累計比較已在 v0.6.9 做了，只呈現事實，見 §5.3）、二代健保補充保費。

## 2. 系統架構

```
            ┌────────────── 使用者的瀏覽器 ──────────────┐
            │                                          │
data/*.csv  │  dist/index.html（單一檔案）              │
data/*.json │   ├─ SP5_DATA（制度數字，build 時內嵌）     │
     │      │   ├─ engine.js（計算引擎，build 時內嵌）    │
     ▼      │   └─ 畫面（HTML＋CSS＋JS）                 │
scripts/    │            │                             │
build.js ───┼──► 產生 ───┘                             │
            │            ▼                             │
            │   localStorage（sp5:data，方案存檔）       │
            └──────────────────────────────────────────┘
```

- **上線的只有一個檔案** `dist/index.html`，放在 GitHub Pages。沒有後端、沒有 API 呼叫、沒有第三方套件。
- **引擎全專案只有一份** `src/engine.js`：瀏覽器和 node 測試用的是同一份程式，畫面上的數字和測試驗證的數字不可能不一致。
- **制度數字和程式分離**：`data/` 裡的 CSV 和 JSON 由 `scripts/load-data.js` 讀取。node 測試直接讀檔；build 時轉成 `window.SP5_DATA` 內嵌進 HTML。

## 3. 資料層

### 3.0 資料治理規則（v0.9.9）

任何新的制度規則加入時，先問三件事：

1. 這是法律邏輯，還是一個數字？
2. 如果是數字，未來會不會改？
3. 如果會改，有沒有生效日期？

**會改＋有生效日 → 放有生效日的 CSV（data/*.csv）**，不放在 JS，也不放在 params.json。其他的數字一律集中在 params.json，程式只讀不寫；畫面與 PDF 的文字一律從同一份資料帶入（`src/app/00-state.js` 的 `LAW`），不自己存制度數字。

每個參數都要能回答「你是誰、從哪來、屬於哪種資料」：

| category | 放哪裡 | 例子 |
| --- | --- | --- |
| annual_data | 有生效日的 CSV | 保費、分級表、生命表、年金化利率、存款利率、健保投保金額上下限、國保遺屬最低保障 |
| legal | params.json | 勞保兩式、法定請領年齡、15 年門檻、遺屬年金一半、舊制退休條件、學制 |
| model_assumption | params.json 的 assumptions | 通膨 2%、勞退基金報酬 3%、晚年多花 75 歲、算到 90 歲、過世後生活費七成 |
| product_rule | params.json 的 product、deposit_input | 試算上限 65 歲、存款利率輸入範圍 |

params.json 每一組都要有 `category` 與 `source`；說明文字（`*note`）**不准用中文再寫一次同一組已有的數值**，數值改了說明不會跟著改（法條條號「第 N 條」是引用，不算）。以上都由 data.test.js 檢查。

**語意一致性測試（tests/semantic.test.js）**：把建置好的網頁內嵌資料改掉一個參數（法規、假設、產品規則、年度資料各數組），檢查引擎、結果頁、提高準確度、調調看、PDF 的資料模型**全部跟著變**，且原本的網頁裡沒有那個新數字。任何一處沒變，代表那裡自己偷存了一份。比掃描字串可靠：測的是行為，不是字面。

### 3.1 依年度的表

國保、健保、上限、存款利率、兩張分級表都有 `effective`（生效日）欄位。引擎用 `pick(rows, 年, 月)` 取「生效日 ≤ 指定年月的 1 號」的最新一列（所以月中生效的列，下個月才會套用）；全部都還沒生效時取最早一列。生命表一個生效日有多列（每個年齡一列），取同一個生效日的那一整組。`status` 欄位：`confirmed`＝生效日查證過；`observed`＝至少從這天起已在使用，正式生效日待查（不編日期）。

官方調整時**加一列新的生效日，不改舊的列**。例如 116 年國保保費公告後，在 `np_premium.csv` 加一列 `2027-01-01`，2027 年起打開網頁就會自動套用。

## 4. 計算引擎（`src/engine.js`）

### 4.1 時間與金額的基準

- **按月計算**：t＝0 是這個月，一個月一步。每個月先收支、再滾一個月的報酬。
- **年齡精確到月**：59.9167＝59 歲 11 個月；退休、請領、還清都發生在某一個月。
- **金額一律是今天的購買力**（實質）。名目固定的金額（房貸、車貸、勞退月退、提前還清的本金）依通膨逐月折算。
- **引擎內部用「元」**；畫面的「萬」只在輸入和顯示時換算。

### 4.2 報酬率與通膨

| 項目 | 預設 | 誰能改 | 說明 |
| --- | --- | --- | --- |
| 通膨 | 2% | 使用者（2%／2.5%／3%） | 薪資、生活費、勞保年金都隨通膨調整，實質不變 |
| 名下的錢 | 存款利率 1.7% | 使用者（活存 0.8%／定存 1.7%／優利 2.0%） | 退休前後同一個利率，不算投資 |
| 勞退基金 | 3% | 不開放 | 政府基金的報酬，屬於制度的一部分 |

實質報酬＝(1＋名目)÷(1＋通膨)－1，再換成月報酬 (1＋年)^(1/12)－1。預設下名下的錢實質每年約 **-0.29%**。

`setRates()` 在建立引擎時和每次 `sync()` 時依 `S.pre.inf`、`S.pre.dep` 重算。壓力測試透過 `assume.infAdd` 在使用者選的通膨上再加。

### 4.3 主要流程

```
輸入 S ──► profile(adj) ──► pensions(P, R) ──► netM / flowsM（每個月的收支）
                                │
             ┌──────────────────┼──────────────────┐
             ▼                  ▼                  ▼
        evalR(P, R)        ledger / monthly     phases / events
   退休前正推、退休後反推     逐年、逐月明細         地圖的階段與事件
             │
             ▼
        earliest(adj, maxAge) ── 逐月找第一個「缺口 ≤ 0 且退休前沒用完」的月份
             │
     ┌───────┴────────┐
     ▼                ▼
 solve / howTo    stressEarliest
 多投入或少花多少      壓力情境
```

### 4.4 核心函式

| 函式 | 作用 |
| --- | --- |
| `profile(adj)` | 輸入轉成模型：月收入、生活費、貸款、每個月的子女費用陣列、勞保勞退估算值、壓力情境的調整 |
| `pensions(P, R)` | R 歲退休時的勞保、勞退、國保、舊制：請領時點、月領金額、年資、一次領金額 |
| `netM(P, Q, t)`／`flowsM` | 第 t 個月的淨現金流；`flowsM` 另外拆出每一項收入和支出 |
| `evalR(P, R)` | 退休前**正推**資產；退休後從終點**反推**所需本金；回傳需要、預估、缺口、退休前用完的時點 |
| `earliest(adj, maxAge)` | **從現在的年紀**逐月找到 maxAge（主結果 65，調整預覽 80）；v0.6.0 前從 55 歲開始 |
| `solve(R, key)`／`howTo` | 二分搜尋要「多投入」或「永久少花」多少才補得上；判斷做不做得到 |
| `ledger`／`monthly` | 按年、按月模擬，標出退休前、退休後用完的時點 |
| `eventsAt`／`impactEvents` | 這個月發生的事、對收支的影響（退休、年金開始、貸款繳完、孩子升學畢業、健保等） |
| `phases` | 地圖的階段：工作期、橋接期、勞退期、雙年金期、勞保期、國保期 |
| `scenario(inputs, sel, opt)` | 調調看與萬一……共用：另建一個引擎，回傳 `{ en, adj, e }`；sel 含 li／inf／end／gap／cut／spend／more（多花，負數＝少花）／save（多存，負數＝少存） |
| `stressEarliest(inputs, sel, opt)` | `scenario(...).e` 的簡寫 |
| `gapYears(gaps)` | 工作空窗依情境分成「勞保勞退都中斷」與「只有勞退中斷」兩類的年數 |
| `validate()` | 輸入檢查，回傳第一個錯誤的白話說明 |

### 4.5 求解方法

- **所需本金**：從終點往回推，`need = max(0, need ÷ (1＋月報酬) － 當月淨流量)`，一路推到退休那個月。
- **預估資產**：從今天往後推到退休那個月。**負資產不滾報酬**；退休前資產變負數就記下時點，該退休時點判定不可行。
- **自我檢查**：拿所需本金再正推一次，退休後的最低點應該剛好碰 0（測試容許 1 元）。

| 制度 | 規則 | 依據 | 驗證 |
| --- | --- | --- | --- |
| 勞保老年年金 | 兩式擇優：W×年資×0.775%＋3,000、W×年資×1.55% | 勞保局 0109187 | FAQ 範例 12,097、19,806 |

## 8.5 PDF 報告（v0.7.0）

**入口**：結果頁方案列右邊的「分享」。**沒有有效的修改 → 單一版本；有（調調看或還沒套用的實際資料）→ 原始 vs 調整後的對照。** 填錯的實際資料不算修改。

**架構**：網頁與 PDF 用同一份資料。
| 層 | 位置 | 說明 |
| --- | --- | --- |
| 資料模型 | `reportModel()`（src/index.html） | 從引擎與網頁現有函式取值：`condModel`（條件）、`compareHtml` 的資料記錄（對照的結果）、`phaseModel`（每個階段與事件，網頁的地圖也用它）、`assumptionsList`（假設，網頁也用它）、`liModel`（勞保比較） |
| 排版 | `src/pdfdoc.js` | 純函式：模型 → pdfmake 的文件定義。瀏覽器與 Node 測試共用。去個資、罕見字替換、加密設定都在這裡 |
| 產生 | 瀏覽器 | 按下產生才載入 pdfmake 與字型；字型存在 Cache Storage；手機用系統分享選單、電腦直接下載。**資料不離開裝置** |

**章節**：每章的標題、說明與第一個內容包成不可拆開的區塊，這一頁放不下就整章換頁（寧可留白，標題不單獨留在頁尾）。前言（含適用範圍、假設）→ 目錄（頁碼自動）→ 一、條件 → 二、結果 → 三、你的錢會怎麼走 → 四、每個階段的收支（金額與事件都左右對照）→ 五、勞保一次領 vs 月領（能選一次領才有）。

**去個資版**：拿掉出生年月（改寫年齡）、**所有年月**（年齡＋年月就能反推出生日）、孩子的出生年月（改寫年齡）、工作空窗的原因（只留幾段、多久）、方案名稱；財務數字保留。頁首的產生日期不算個資。

**密碼**：預設加密碼、輸入兩次、至少 8 個字；可以取消。AES-256（R5，見 11.2）。

**字型**：`scripts/build-font.py` 從 `fonts/source/` 產生子集 `fonts/kai-subset.ttf`（約 3.8 MB）與 `fonts/kai-chars.txt`。優先用全字庫正楷體（TW-Kai*.ttf），沒有就用文鼎 PL 中楷。授權條款放在 `fonts/`，PDF 頁尾寫出字型名稱。

## 8.6 畫面程式的結構（v0.8.0）

- `src/app/` 依功能分 15 個檔案（狀態、快速開始、每個階段、調調看、對照、夫妻模式、提高準確度、結果、PDF、存檔、備份、使用統計、對話框、方案、事件），檔名前的數字是接起來的順序。它們**不是獨立模組**：build 時接起來、包在同一個函式裡，彼此共用變數（`S`、`C`、`EN` 與各種函式）。
- 狀態分兩個物件：`S` 只放使用者的輸入與畫面狀態（存檔只存 `IN_KEYS` 列出的欄位）；`C` 放畫面算出來的暫存結果（`ctx`、`heroHtml`、`Rorig`、`Radj`、`preEst`），每次重算、不存檔。
- **跳脫的規則**：存檔或使用者輸入的文字，放進 HTML 前一律 `esc()`。會同時給 PDF 用的文字（例如 `preVal()`）維持純文字，在放進 HTML 的那一刻才跳脫；`toast()` 與對話框標題用 `textContent`，不用跳脫。畫面測試有四輪攻擊測試把關（存檔每個欄位、名稱與 id、提高準確度每個欄位、模擬驗證失效）。
- ESLint 由 `scripts/lint.js` 執行：一般檔案照常檢查，`src/app/*.js` 接起來再檢查，錯誤行號換算回原檔。

## 8.7 方案匯出／匯入（v0.8.1）

- **入口**：方案清單的「備份」卡：匯出所有方案、匯入方案、清除這台裝置的資料。
- **檔案**：`退休試算方案_YYYY-MM-DD.json`。外層 `{app: 'sp5-retirement', kind: 'scenarios', format: 1, version, exported, encrypted}`；不加密時直接放 `list`（每個方案的名稱、存檔資料、存檔時間）；加密時放 `kdf`、`cipher`、`data`。`format` 是檔案格式的版本，比網頁認得的新就請使用者重新整理。
- **加密**：AES-256-GCM；金鑰由密碼經 PBKDF2-SHA256 計算 60 萬次；每次匯出的鹽（16 bytes）與 IV（12 bytes）都是新的亂數。密碼至少 8 個字、預設加上；忘記無法找回。加密後檔案裡看不到任何名稱或數字。
- **匯入**：先預覽、勾選；**一律新增成新方案，不覆蓋**；同名加「（匯入）」；受 10 個上限。檔案內容一律當外來資料：只取認得的欄位、轉成該有的型別、長度設上限，放進畫面前跳脫。新裝置（原本沒有方案）匯入後直接切到第一個匯入的方案。
- **出錯**：不是 JSON、不是這個網站的檔案、比較新的版本、沒有方案、超過 2 MB、密碼不對（竄改過的檔案也會解不開），各自說明，並寫明「你的方案沒有任何改變」。

## 8.10 夫妻模式（v1.0.0 已上線；本節保留設計當時的紀錄，現況以「0. 現況摘要」與版本紀錄 v1.0.0-beta.1～v1.0.0 為準）

**來源**：Threads 公測留言（夫妻要一起考慮；各自假設對方會負擔，加起來會破洞），以及外部評論提過的雙人模式。畫面草稿：claude.ai 畫布「夫妻模式：畫面草稿（手機版）」。

**要回答的問題**：夫妻幾乎不會同一個月退休，所以問的不是「我們幾歲退休」，而是「**我想幾歲退休，另一半最快什麼時候可以跟著退？**」誰的退休年月早，誰就是先退（早一個月也是），一律用日曆比，不用年齡比（兩人年齡不同，用年齡比會顛倒）。

**畫面**
- 入口：「你想怎麼算？」我自己／我和另一半。問的是規劃方式，不是婚姻狀態（單親、各管各的夫妻都用「我自己」）。舊方案一律視為「我自己」；方案清單標示模式。
- 快速開始：三個頁籤。你、另一半各填自己的三格（出生年月、幾歲開始工作、每月實際入帳），按「下一步」等於按下一個頁籤；我們家填全家共有的（名下可動用的錢、每月生活費、房貸、孩子，孝親費雙方各一格、金額可不同），按「算」。頁籤上顯示「已填 3 / 3」或「還沒填」。稱呼可自訂，不預設性別。
- 三個參考方案：你先退到底（你能退多早就多早，另一半撐到夠為止）、一起退（同一個月，最早的那個月）、另一半先退到底。每個方案兩條線（你、另一半），橫軸是年份；每條線三種狀態：工作中（綠）、已退休但年金還沒開始（橘）、有年金（灰藍）。兩條同時是橘色＝全家只靠存款；一條綠一條不是綠＝一份薪水撐全家。每個方案顯示一份薪水撐全家幾年、只靠存款幾年、90 歲剩多少（最快的組合剩得很少是正常的，要附說明）。
- 滑桿：可切換調「你」或「另一半」的退休時間，算出另一方最快的年月、誰先退、差多久、換算比例（「你每多做 1 年，另一半可以早 1 年 2 個月」），加兩條線。
- 取捨曲線：**不做**。三個方案、滑桿、兩條線已經回答了所有問題；曲線兩軸都是年齡，一般人不好讀。
- 調調看：退休時間交給滑桿。你可以決定的：全家每月花費、全家每月多存、活到（你、另一半各自）。萬一：收入中斷、收入減少（你、另一半各自，可同時設）、晚年多花（全家）、通膨、存款利率、勞保只領到（兩人一起打折，制度風險）。對照表比的是目前滑桿選的組合，原始 vs 調整後，加原始與調整後的兩條線。
- 提高準確度：三個頁籤（你、另一半、我們家）。個人的：勞保、勞退、工作空窗、勞退舊制、勞保請領方式。我們家：存款利率、通膨。健保依附是法律規定，自動處理，不需要設定。

**計算規則（已定案）**
- 家庭現金流：兩人各自的制度時間軸（薪水、勞保、勞退、國保、健保、保費）＋共同支出（生活費、房貸、孩子、雙方孝親費）＋共同存款。錢一定合併算：一人先退就是靠另一人的薪水和共同存款撐。
- 一人退休後，全家生活費**不變**（想調的人用調調看）。
- 健保（v0.9.8 依法修正）：無職業的配偶**一定要**依附有工作的一方（全民健康保險法第 2、12 條），不能自選第六類，所以**沒有「各自繳」的選項**。依附**不是免費的**：在工作的一方多算一份眷屬保費（投保金額 × 5.17% × 30%），月入 6.5 萬約 1,008，可能比第六類 826 還貴；孩子也是眷屬，眷屬最多算 3 人（已有 3 個孩子就不用多繳）。兩人都沒工作：一人投保第六類當戶長，其餘依附，826 ×（1 ＋ 眷屬數）。
- 一方過世（到達他自己的「活到」）：他的勞保、勞退、國保年金停止；全家生活費降到**七成**；算到兩人中較晚過世的那一位。v0.9.8 補上：**勞保、國保遺屬年金**（另一方 55 歲以上、沒有工作時，自己的年金與過世者的一半取高；最低：勞保 3,000（條例寫死，params.json）、國保 4,049（data/np_benefits.csv，每 4 年依 CPI 調整）；過世者一次請領就沒有）；**勞退專戶餘額**（月領期間過世，剩下的錢在過世當月回到家裡，例如 60 歲開始月領、70 歲過世約剩 146 萬）。
- **有人退休之後，存款就不能是負的**（v0.9.7 測試發現）：單人模式在還在工作時允許存款暫時為負（例如房貸提前還清的大筆支出，之後薪水會補回來），退休後才不行。夫妻模式用同一條規則，但起點是**兩人中最早退休的那個月**：家裡已經少了一份薪水。所以另一半比較早退休時，原本單人算得過的情況可能會變成不夠；這是正確的結果，畫面要能說明原因（例如「另一半退休後，2032 年房貸提前還清那個月，存款會不夠」）。
- 引擎範圍外的月份要明確處理：原型在「剛好滿 90 歲的那個月」得到 NaN，而 NaN 與 0 比較永遠為否，會讓「存款會不會用完」的判斷直接放行。正式版要加測試：所有月份的現金流都是數字。

**原型發現（2026-10-06，用單人引擎拼的原型，你 1985-03 月入 8 萬、另一半 1988-07 月入 6.5 萬、存款 300 萬、生活費 7 萬、房貸 2 萬還 20 年、兩個孩子）**
- 換算比例很穩定（你多做 1 年，另一半早 1 年 1～4 個月），大致等於兩人薪水的比例，沒有預期中的「划算點」（年金門檻造成的跳動）；所以畫面不強調划算點，直接顯示換算比例。年資卡在 15 年附近的家庭可能會有轉折，正式版要用更多情境驗證。
- 換算比例不對稱：你多做 1 年，另一半早 1 年 2 個月；另一半多做 1 年，你只早 10 個月（薪水高的一方多做，對家裡幫助較大）。
- 一起退是三個方案裡唯一有「只靠存款」的（2 年 1 個月）；兩個極端方案一直有一份薪水。
- 全家每月少花 5,000，在「你 55 歲退休」下，另一半可以早 3 年，但多出 1 年 7 個月只靠存款。

**架構**：放在 SP5 裡，不另開專案（規則只能有一份）。v0.9.7 已完成引擎拆層：personFlowsM／householdFlowsM、role: 'person'、timeline、household 組合器（夫妻規則的掛勾 livingFactor、premiumWaive 已備好，v1.0 接上）。引擎拆成三層：制度規則（不動）→ 一個人的時間軸 → 家庭現金流。單人模式＝只有一個人的家庭，兩種模式走同一條程式路徑。畫面程式分開放（夫妻模式另一組 src/app 檔案），共用引擎、資料、樣式、PDF、匯出入、GA、回報問題。

**版本**：v0.10 引擎拆三層（單人結果必須一模一樣，用全部現有測試把關）→ v0.11 夫妻的家庭現金流與求解（先用測試驗證，含上面的不變式：兩人互換、對稱、所有月份都是數字、滑桿單調）→ v0.12 夫妻模式畫面 → v1.0。

**之後再決定**：夫妻版 PDF 與分享；從「我自己」切到夫妻時是否帶入「你」的資料；另一半的資料是別人的個資，是否提醒先跟另一半說；夫妻模式的 GA 事件。

## 9. 建置與部署

```bash
npm install       # 第一次：jsdom、pdfmake、pdf.js（開發與 build 用）
npm test          # 引擎、規則、persona、資料、畫面結構、驗收（不需要套件）
npm run build     # data/ → dist/index.html；PDF 程式庫與字型 → dist/vendor、dist/fonts；預覽單檔 dist/preview.html
npm run test:ui   # 畫面操作
npm run test:pdf  # PDF 報告
npm run check     # 以上全部
npm run font      # 重新產生楷書子集（scripts/build-font.py，需要 Python 的 fonttools）
```

- `dist/` 有三樣東西：`index.html`（網頁本身）、`vendor/pdfmake.min.js`、`fonts/kai-subset.ttf`（按下「產生 PDF」才下載）。
- `dist/preview.html` 把程式庫與字型都內嵌（約 6.5 MB），給只能放單一檔案的預覽環境用；GitHub Pages 用的是 `index.html`。

- push 到 `main`：GitHub Actions 先 `npm ci`，再跑引擎、畫面操作、PDF 三組測試，**全部通過才發布** GitHub Pages。
- repo 必須是 Public（免費方案限制）；網址 `https://<帳號>.github.io/<repo>/`。
- 網頁上一律使用平台名稱；程式碼、資料夾、localStorage 前綴維持 SP5。
- commit 前確認 git 用 GitHub 的 noreply email；測試資料一律虛構。

## 10. 決策紀錄（摘要）

| 決定 | 理由 |
| --- | --- |
| 不靠投資，名下的錢用存款利率 | SP5 回答「收入減支出能不能提早退休」；投資是 SP2 的範圍；定存會被通膨吃掉，所以不是 0% |
| 通膨不提供低於 2% 的選項 | 避免使用者把結果調得太好看 |
| 勞保請領年齡開放選擇 | 這是人生決策，不是衡量的尺 |
| 引擎按月計算、最早時點精確到月 | 輸入本來就到月；制度按月；按年有不一致 |
| 壓力測試分三類、一次開一類 | 六組攤開太多 |
| 「提早退休」併入現金流地圖 | 「想調整看看」只放能調整的東西；地圖回答「如果在 X 歲退休會怎樣」 |
| 退休時間用下拉選單 | 左右滑不容易發現；選項可以直接寫出每個時間點的結果 |
| 選別的時間點，大數字不變 | 大數字永遠是答案；地圖和壓力測試都是「看看」 |
| 子女每個階段分開填 | 公私立、國內外差距好幾倍 |
| 勞退舊制放提高準確度並主動提醒 | 和勞保、勞退並列；用出生年月＋開始工作年齡判斷可能有舊制 |
| 只留一個色塊 | 四個色塊讓眼睛不知道先看哪裡 |
| PDF 在瀏覽器產生（v0.7.0） | 資料不上傳；GitHub Pages 不需要後端；版面一致、可加密、可有目錄 |
| PDF 程式庫與字型自己放、不用 CDN（v0.7.0） | 維持「網頁不對外連線」 |
| 網頁與 PDF 共用資料模型（v0.7.0） | 從畫面抓文字會在網頁改字時悄悄壞掉 |
| 去個資版拿掉所有年月（v0.7.0） | 年齡＋年月可以反推出生年月 |
| 填錯當場擋下、不算修改（v0.7.0） | 錯的值不該變成「條件」，也不該讓對照表消失 |
| PDF 章節標題不單獨留在頁尾（v0.7.1） | 寧可留白換頁；用不可拆開的區塊做，不用換頁規則（pdfmake 的換頁判斷看的是第一輪排版，不可靠） |
| PDF 密碼至少 8 個字（v0.7.0） | pdfkit 只支援 AES-256 的 R5，用長度補強密碼驗證的弱點 |
| 勞保未滿 15 年不再算成 0（v0.6.11） | 舊版把未滿 15 年的人算成「沒有勞保」，最影響想提早退休的人；改為老年一次金或併計國保月領 |
| 併計國保時預設月領（v0.6.11） | 月領是活越久越多的保障；勞保區塊寫明也可以選老年一次金 |
| 農民不納入（v0.6.12） | 農保沒有老年給付，改由老農津貼與農退儲金保障；勞保轉農保的人還要處理年資保留。需求確認後再做獨立版本 |
| 國保只用 B 式（v0.6.12 確認） | 2023/10 以後領勞保老年給付者不得選 A 式；以勞保局國保試算頁核對 |
| 寫明適用範圍（v0.6.11） | 公教軍人填完會得到完全錯的答案卻不知道錯在哪，比任何數字都重要 |
| 勞保一次領只比較、不建議（v0.6.9） | 呈現兩條累計線與交叉年齡；「活多久」只有使用者自己能判斷 |
| 一次領比較含國保（v0.6.9） | 2023/10 起一次領後不得保國保；只比勞保會讓一次領看起來比實際好 |
| 資格判斷不了就明說（v0.6.9） | 「開始工作早於 2009」不代表當時有保勞保；讓查過勞保局的人自己勾選確認 |
| 敏感題目寫明用途、只在需要時問（v0.6.9） | 性別、同一家公司年資、工作空窗、子女、孝親費、健保依附；資料只存在使用者裝置 |
| 「那天需要多少」拉到前面（v0.6.9） | evalR 的 need 是最有用的一句話，也是交接給 SP2 的橋；在最快時間點跟「會有」合成一句，避免重複 |
| 從現在的年紀開始算（v0.6.0） | 測試者卡在 55 歲下限三次；她其實 53 歲 6 個月就能退休 |
| 試試看＋壓力測試＋地圖選單 → 調調看（v0.6.0） | 四個地方都在回答「如果……會怎樣」；統一成調整器＋整頁預覽 |
| 「多投入」改回「多存」（v0.6.0） | 平台不靠投資，「投入」容易被誤會成投資；雙向調整時「多存／少存」較自然 |
| 算到幾歲只放在萬一的「活到」 | 活多久不是查得到的事實，是不確定的事；原始一律 90 歲，想改基準就存成新方案 |
| 晚年多花從 75 歲起 | 固定年齡、不跟「活到幾歲」連動；壽命無法預知，不用「最後幾年」來描述 |

### 11.2 已知限制

- **PDF 加密是 AES-256 的 R5**：pdfkit 只支援 R5，密碼驗證只做一次 SHA-256，猜密碼比 R6 快。內容本身的加密相同（AESV3）。因此密碼至少 8 個字。
- **PDF 字型目前是文鼎 PL 中楷**（Arphic 公眾授權）：全字庫正楷體的官方下載站在建置環境無法連線，轉載版授權不明。英數字是等寬字形。
- 字型子集收錄 5,567 字（Big5 常用字＋程式用到的字）；方案名稱有子集外的罕見字時，PDF 裡印成「□」。

- **只算勞保、勞退**：公保、軍保、農保不算，公務員、教師、軍人不適用（快速開始第一頁寫明）。
- 一次領的稅（退職所得）、長照的政府補助、65 歲以後繼續工作未計入。
- 國保年資只算退休後到 65 歲；在職前或空窗期間繳過的國保年資沒有問。
- 勞退月退實際每 3 個月發一次（季發），SP5 按月攤開計算。
- 農民（農保、老農津貼、農民退休儲金）不適用：農保沒有老年給付，老年保障是另一套制度；快速開始寫明。
- 二代健保補充保費未計入。
- 健保第六類只算本人；眷屬的保費假設由在職配偶負擔。
- 勞退月退每 3 年重新核算未模擬。
- 薪資實質成長固定為 0%。
- 本結果是依固定假設推估的門檻，不是預測，也不構成投資建議。
